# E2E 통합 테스트

이 프로젝트는 데이터 테이블마다 생성 함수를 따로 두고 있고, 각 함수는 개별 테스트로 검증한다. 그런데 실제로 사용자가 실행하는 진입점은 이 함수들을 순서대로 엮는 `main()` 하나다. 그동안은 이 전체 흐름을 처음부터 끝까지 한 번에 돌려보는 테스트가 없었다.

그래서 새 단계를 추가하거나 함수 사이의 연결을 바꿨을 때, 개별 함수는 멀쩡한데 연결만 어긋나는 문제를 놓칠 수 있었다. E2E 통합 테스트는 바로 이 빈틈을 메운다.

## 어디에 있나

테스트는 `tests/test_pipeline.py` 한 파일에 모여 있다.

## 어떻게 동작하나

방식은 단순하다.

1. `main()`을 작은 규모로 실제 실행한다. 유저 200명, 상품 50개 정도라 1초 안에 끝난다.
2. 결과는 매번 새로 만드는 임시 폴더에 쓴다. 저장소나 다른 테스트에 영향을 주지 않는다.
3. 임시 폴더에 쌓인 결과물을 다시 읽어서 기대한 대로 만들어졌는지 확인한다.

파이프라인은 딱 한 번만 실행하고, 여러 검사가 그 결과를 나눠 쓰도록 했다. 그래서 검증 항목이 많아도 테스트가 느려지지 않는다.

## 무엇을 확인하나

| 확인 항목 | 설명 |
|---|---|
| 전 구간 실행 | `main()`이 처음부터 끝까지 오류 없이 끝나는가 |
| 산출물 위치 | 차원 데이터는 단일 파일로, 팩트 데이터는 폴더로 올바른 자리에 생기는가 |
| 파티션 구조 | 팩트 폴더 안에 날짜별 `dt=` 파티션 폴더가 생기는가 |
| 스키마 | 다시 읽었을 때 컬럼 구성이 기대한 것과 같은가 |
| 파티션 키 | `dt` 값이 실제 타임스탬프의 날짜와 일치하는가 |
| 테이블 연결 | 주문, 주문상세, 행동로그가 회원이나 상품 같은 기준 데이터를 올바르게 가리키는가 (디스크에 저장된 상태 기준) |
| 옵션 반영 | 실행할 때 넘긴 유저 수, 상품 수가 결과에 그대로 반영되는가 |

세부 분포나 같은 시드면 같은 결과가 나오는지 같은 항목은 개별 함수 테스트가 이미 맡고 있다. 그래서 여기서는 그런 부분을 중복으로 다루지 않고, 함수들의 연결과 저장 결과에만 집중한다.

## 실행 방법

이 테스트만 돌리려면:

```
uv run pytest tests/test_pipeline.py -v
```

전체 테스트를 돌리려면:

```
uv run pytest
```

## 결과

통합 테스트는 8개이고 약 0.7초 만에 끝난다. 전체 테스트는 77개가 모두 통과한다.
